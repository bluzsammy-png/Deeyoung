QuantEdge Pro — Core Data Model (PostgreSQL, per-user isolation)
Entities grouped by domain. Every user-owned row carries userId; cross-user access is denied at query level (row scoping) and verified by security tests (§58).
IDENTITY & SAAS
User PK
id, email (verified), passwordHash, mfaSecret?, role (USER/ADMIN…), createdAt, status
Session PK
id, userId FK, device, ip, createdAt, expiresAt, revokedAt?
Subscription
id, userId FK, plan, status, billingProvider (STRIPE / STOREKIT), externalId, periodEnd
Entitlement
id, userId FK, feature (SENTINEL/BACKTEST/AI…), limit, source — server-checked only
UsageEvent
id, userId FK, provider, service, units, estCostMicros, at (metering §31)
ProviderKey (BYOK)
id, userId FK, provider, encSecret (server-side, never returned), verifiedAt
MARKET DATA & INTELLIGENCE (shared)
Watchlist
id, userId FK, name, isDefault
WatchlistItem
id, watchlistId FK, symbol, addedAt
Catalyst
id, symbol, headline, source, url, category, sentiment, relevance, strength, publishedAt (§11 — never fabricated)
MarketRegime
id, state, confidence, drivers (json), assetClass, windowStart/End, explanation
SymbolMeta
symbol, name, sector, assetClass (EQUITY/ETF/CRYPTO), tickSize, delayStatus
SIGNALS & PERFORMANCE
Signal PK
id, symbol, side, score, confidence, regimeId FK, catalystId?, strategyId?, createdAt
SignalFactor
id, signalId FK, name (EMA/VWAP/RSI/MACD/BB/relVol/ROC/ATR…), contribution, value
SignalOutcome
id, signalId FK (1:1), entry, stop, target, exitAt?, result (WIN/LOSS/OPEN/EXPIRED), rMultiple, durationMin
Strategy / StrategyVersion
id, ownerId FK, params (json), version, status (DRAFT/PAPER/ACTIVE)
Backtest
id, strategyVersionId FK, period, metrics (json: CAGR, Sharpe, maxDD, PF…), status
TRADING & EXECUTION
Order
id, userId FK, signalId?, side, qty, type (MKT/LMT/STP), status, idempotencyKey (unique), providerRef
Fill
id, orderId FK, qty, price, fee, slippage, at (realistic fill model §20)
Position
id, userId FK, symbol, qty, avgPx, stop, target, openedAt, closedAt?
BrokerConnection
id, userId FK, provider (QE_PAPER / ALPACA_PAPER), encSecret, status, lastCheckAt
RISK & SENTINEL (per user)
RiskProfile
id, userId FK (unique), riskPct, maxPositions, maxNotional, dailyLossCap, weeklyLossCap, maxDailyTrades, minRR, minLiquidity, sessions, allowedAssets/Strategies
BotConfig
id, userId FK (unique), mode (OBSERVE/APPROVE/DELEGATE), enabled, watchSymbols, pendingExpirySec — default OBSERVE + off
Approval
id, userId FK, orderDraft (json), state (PENDING/APPROVED/REJECTED/EXPIRED), single-use token, expiresAt, decidedAt
SentinelState
id, userId FK, state (ACTIVE/PAUSED/RISK_LOCKED/BROKER_DISCONNECTED/DATA_UNAVAILABLE/EMERGENCY_STOP…), reason, since
OPS, COMPLIANCE & NOTIFY
AuditEvent (append-only)
id, actorId?, action, targetType, targetId, detail (json), at, prevHash + hash (tamper-evident chain §45)
SystemEvent
id, type, severity, service, detail, at (observability §44)
Notification
id, userId FK, type, importance, payload (json), deepLink, readAt?
NotificationDelivery
id, notificationId FK, channel (WEB_PUSH/EMAIL/MOBILE_PUSH), state (QUEUED/SENT/DELIVERED/OPENED/FAILED/RETRY)
NotificationPreference
id, userId FK, eventType, channels, quietHours, minImportance
Key relationships (1 — N unless noted)
User — Watchlist · Order · Position · Approval · RiskProfile (1—1) · BotConfig (1—1) · Subscription · Entitlement · UsageEvent · Notification · AuditEvent Signal — SignalFactor (1—N) · SignalOutcome (1—1) · Order (0—1) Order — Fill (1—N) · Approval (0—1, single-use) MarketRegime — Signal (labels every signal) Strategy — StrategyVersion (1—N) — Backtest (per version) AuditEvent — hash chain (tamper-evident)
